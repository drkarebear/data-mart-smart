Enough evidence to tell the story, not a data dump

I'm Writing a Program Review

Use DataVista for the broad student and program story, Data Mart only where a specific report adds useful detail, and local data for current operational reality.

Build the evidence in three layers

1

DataVista: the broad story

Start with multi-year program activity and student outcomes. Depending on the program and view, useful measures can include sections, enrollments, online/DE sections, calculated FTES, success, completion, transfer, and disaggregated outcomes.

Use the DataVista guide

2

Data Mart: targeted detail

Pull a Data Mart report only when it answers a question that DataVista does not answer clearly enough. Common examples include Grade Distribution, Course Details, or a report structure you need to export and examine directly.

Use the Data Mart guide

3

Local data: current context

Add the information that statewide systems cannot supply in real time, such as current enrollment, waitlists, fill rates, cancellations, scheduling patterns, FTEF, staffing, and locally defined cohorts or interventions.

Know when local data comes first

A lean program-review evidence set

You usually do not need every available metric. Start with a small set tied to the questions the review actually asks.

Open the quick evidence map

1. Scale and demand

What happened to sections, enrollments, students, and instructional activity over several comparable years?

2. Student outcomes

What happened to course success, progression, completion, transfer, or other outcomes that fit the program?

3. Equity

Do outcomes differ across defined student groups, and are the denominators and suppression rules clear?

4. Current operations

What do local scheduling, fill, waitlist, staffing, modality, and resource data add to the statewide picture?

5. Interpretation

What does the evidence show, what does it not establish, and what question should the department investigate next?

A repeatable workflow

  1. Write the CPR question in plain language.
  2. Choose the source that best matches that question.
  3. Document population, timeframe, measure, and denominator.
  4. Use three to five comparable years when making a trend claim.
  5. Add local context before explaining why a pattern occurred.
  6. End with an action or a next inquiry, not just a chart.

Program review is not improved by more spreadsheets

A smaller evidence set with clear definitions is usually stronger than a long list of disconnected counts. If a measure does not inform a program-review question or decision, leave it out.

Use the browser tools where they actually help

The current Program Review Dashboard and export interpreter are strongest with Data Mart exports. They can help organize comparable evidence without turning unlike measures into one score.
